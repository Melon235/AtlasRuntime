The digest is `canonical_digest(preregistration_payload())`. It covers §1–§7 and nothing else: it
contains no absolute path and no approval state. If any task text, oracle, requirement, DAG, arm or
budget parameter changes, the digest changes.

The superseded C2-A digest is kept as a literal constant in `protocol.py` and is never recomputed.
The R1 digest is pinned in the same module before any check compares against it, so "the payload
still hashes to the same value" is a comparison with a stored identity, not a hash of the current
code against itself. `docs/closure-2a-r1-review-repair.md` records why the two digests differ.

## 2. Release boundary

The agent workspace contains only the seed: source, `docs/INTERFACE.md` and `test_public.py`. The
hidden oracle and the reference implementation live in this repository
(`experiments/evaluation/closure2/catalog.py`).

**Therefore these are not secret held-out tasks.** What is held out is the workspace the agent sees.
Every published result must carry that sentence; the tasks must not be described as fully
unpublished.

---

## 3. Frozen arms

See `docs/closure-2-fairness-protocol.md` §1 for the table and the per-arm config digests. The
matrix is `N0, N1, A0, A1-L, A1-P, A2-P`; no arm may be added or dropped without a new version.

An arm digest now covers the **effective content** of its YAML config, not only its file name: a
change to `provider.model`, `tools.*`, `sandbox.*` or any other effective key moves both the arm
digest and the registration digest. Comment and formatting edits do not.

## 4. Budget protocol — parameters frozen, approval separate

| Knob | Single | Multi |
|---|---|---|
| max turns | 36 | 12 × 3 = 36 theoretical |
| run token budget | 260 000 | 260 000 |
| max tool calls | 90 | 90 |
| wall clock | 1800 s | 1800 s |
| temperature / `max_tokens` | 0.0 / 8000 | 0.0 / 8000 |
| image, CPU, memory, network | `atlas-uat-python:3.12`, 1, `1Gi`, `none` | same |

These parameters are inside the frozen payload: changing any of them changes the registration
digest, which is the point.

The **approval** is not a parameter and is not inside the payload. It lives in
`protocol.APPROVAL_RECORD`:

```python
APPROVAL_RECORD = {
    "status": "PENDING_OWNER_APPROVAL",
    "approved_digest": None,
    "approved_by": None,
    "approval_commit": None,
    "approved_at": None,
}
```

Rules enforced by `protocol.approval_gate()` and `protocol.require_execution_approval()`:

1. `execution_ready` is true only when the status is `APPROVED` **and** `approved_digest` equals the
   digest currently frozen **and** an approver, an approval commit and a timestamp are present.
2. An approval naming any other digest fails closed; a live run must not start.
3. Moving the record from pending to approved does **not** change the frozen digest — verified by a
   unit test and by the preflight's `approval_outside_frozen_identity` check.
4. `require_execution_approval()` raises `PermissionError` while the gate is not ready. It is the
   only sanctioned entry point for a live Closure-2B run; offline preflight never calls it for a run.

**Closure-2B must not start until the owner changes this record in a new commit**, because approving
the budget after seeing a pilot is not preregistration. This revision does not approve anything.

## 5. Planned measurements (not executed here)

| Cell | Left | Right | Question |
|---|---|---|---|
| native-vs-atlas-single | N0 | A0 | whole-system single-worker comparison |
| native-vs-atlas-multi | N1 | A1-L | whole-system multi-worker comparison |
| layout-ablation | A1-L | A1-P | prompt layout only |
| topology-ablation-atlas | A0 | A1-P | decomposition with the context plane on |
| topology-ablation-native | N0 | N1 | decomposition inside one engine |
| router-admission | A1-P | A2-P | router decision, audited offline |

**Repetitions:** 3 paired repetitions per cell as the minimum. Arm order rotates per repetition;
tasks × repetitions are the outer loop. No arm is completed before another starts.

**Primary metric:** independent oracle correctness. **Secondary:** `TASK_SUCCESS`, provider prompt
tokens, provider cache hit/miss, estimated cost, agent latency, end-to-end latency, model calls, tool
calls, budget violations, execution overlap, context delivery correctness, safety/environment
failures.

**Reporting rules:** a success rate never hides budget overruns; cost is labelled provider-usage or
estimate; cache hit/miss stays `Unknown` without a provider-reported split; cache hit rate never
substitutes for cost.

## 6. Data exclusions

Allowed, applied identically to every arm, with the run kept in the ledger and its reason recorded:

1. a run whose sandbox never became healthy (environment failure before any model call),
2. a run killed by the operator,
3. a run whose **oracle environment** failed (oracle timeout / sandbox failure on the oracle side).

Never allowed: dropping a run because its deliverable failed, because it exceeded the budget, or
because it came from one arm that looked bad.

---

## 7. Cells this design does not support

1. **Router-assisted vs static multi when the router refuses the DAG.** A2-P collapses to the single
   worker, so it is not a multi-worker cell.
2. **Single vs multi across different tasks.** Topologies are compared only inside one task.
3. **A Context-Plane-only attribution of a Native-vs-Atlas difference.** The engines differ in
   execution control, tool organisation and budget enforcement too.
4. **Any cost claim from a run whose provider cache split is `Unknown`.**
5. **Any statistical claim from a single repetition.**

## 8. What must be verified before Closure-2B runs anything

```bash
python -m experiments.evaluation.closure2.preflight \
  --out experiments/results/closure2/preflight-r1.json
```

1. `status == "PASSED"` and all 60 checks true.
2. `preregistration_digest == 3080f313…` (this document) **and** equal to
   `frozen_preregistration_digest` in `protocol.py`.
3. `router_policy.digest == 5e13c910…`.
4. `execution_ready == true`, which requires `approval.status == "APPROVED"` with
   `approved_digest == 3080f313…` and an approver, commit and timestamp.
5. The three `router_gate` records are unchanged: P1/P2 `delegate_parallel` + `DELEGATION_ADMITTED`
   with two disjoint wave-0 workers, N1 `direct` + `SHARED_WRITE_RISK` + `UNSTABLE_INTERFACE` with
   `GATE_2_DEPENDENCY_COUPLING`.

A passing `status` with `execution_ready == false` is the expected state for this stage: the offline
design is verified, the live pilot stays closed. The two facts must never be reported as one.

If the digest differs, the tasks or the budget changed: stop, cut a new benchmark version, and do
not silently re-freeze.

## 9. Router decisions at preregistration time

| Task | Route | Reason codes | Blocked gate | Wave 0 |
|---|---|---|---|---|
| P1 | `delegate_parallel` | `DELEGATION_ADMITTED` | — | `aggregate`, `parse` (2, disjoint) |
| P2 | `delegate_parallel` | `DELEGATION_ADMITTED` | — | `csv`, `json` (2, disjoint) |

P1 and P2 were admitted **because** the write sets are disjoint and the interface contract is proven
against the public fixture. N1 is refused because both candidate steps must edit
`lifecycle/state.py`. No router field, threshold or evidence item was changed to produce these
decisions; the policy digest is identical to the one recorded in Closure-1. The decisions are
asserted as a gate (`preflight.router_gate`), not merely recorded, so a future drift fails the
preflight even while the policy digest stays identical.
